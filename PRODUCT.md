# Product

## Register

product

## Platform

web

## Users

The primary users are self-hosters, developers, and AI image creators who configure GPT-compatible image APIs and manage generated assets on infrastructure they control. They use the product as an operational workspace for repeated image-generation and editing workflows rather than as a public consumer experience.

## Product Purpose

GPT Image Panel brings API configuration, image generation and editing, job tracking, and local gallery management into one workspace. It succeeds when users can move reliably and quickly from configuring an upstream API to generating or editing an image, then finding, reusing, and downloading that image without switching tools.

## Positioning

A self-hosted, all-in-one workspace for GPT-compatible image APIs where users retain control of configuration, jobs, and image data.

## Brand Personality

Calm, precise, and trustworthy. The interface should take cues from Linear's restrained hierarchy, fast workflows, and clear system states.

## Anti-references

The product should not feel like a neon creative toy. Avoid high-frequency animation, exaggerated gamification, and visually loud feedback that competes with the user's work.

## Design Principles

1. **Keep the workflow continuous.** Make configuration, generation, editing, job tracking, and gallery reuse feel like one connected task rather than separate tools.
2. **Make user control visible.** Clearly expose the configuration, task, and storage states that matter in a self-hosted system.
3. **Communicate system state precisely.** Remote and asynchronous operations should always provide trustworthy progress, success, and failure feedback.
4. **Use quiet density.** Favor restrained hierarchy and efficient, predictable controls over decorative motion or playful spectacle.
5. **Make access a default quality.** Target WCAG 2.2 AA with keyboard operability, visible focus, sufficient contrast, screen-reader labels, responsive layouts, and reduced-motion support.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Core workflows must remain usable with a keyboard and screen reader, focus must stay visible and predictable, text and controls must maintain sufficient contrast, responsive layouts must avoid overflow, and motion must respect reduced-motion preferences.
